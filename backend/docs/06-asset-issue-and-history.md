# 领用执行单与资产履历

## 1. 为什么审批通过后不直接改变资产状态

审批通过表示组织授权领用，不代表仓库已经交付实物。若流程结束就直接把资产改成“使用中”，会造成系统状态早于真实业务，也无法记录实际经办人。因此平台增加领用执行单，将“授权”和“执行”分开。

```text
领用申请 → 部门/资产管理员审批 → 待执行领用单 → 实物交付 → 台账更新 + 履历生成
```

## 2. 一致性与并发控制

执行接口在一个数据库事务内完成以下操作：

1. 校验执行单仍为待执行，来源必须是审批完成的领用申请。
2. 校验每一行都关联唯一、存在且当前有权访问的库存资产。
3. 以“资产主键 + 库存状态”为条件更新台账；更新数量不是 1 时判定发生并发变化。
4. 保存资产状态、部门、保管人、地点的变更前后快照。
5. 通过执行单乐观锁记录执行人和时间并完成单据。

接口重复提交防护用于过滤用户快速连点；数据库唯一约束保证同一申请只生成一张执行单；条件更新和乐观锁处理并发；事务保证台账、履历、执行单三者要么全部成功，要么全部回滚。

## 3. 面试说明口径

可以表述为：基于 RuoYi-Vue-Plus 的认证、组织和数据权限能力，独立设计资产申请后的执行闭环。没有把审批完成等同于业务完成，而是增加待执行单和不可编辑履历；通过幂等、乐观锁、条件更新和事务解决重复生成、重复点击和并发领用问题。

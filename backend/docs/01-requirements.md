# 第一至四阶段需求说明

## 1. 用户与角色

- 资产管理员：维护分类、创建和维护资产台账。
- 部门资产负责人：在数据权限范围内查看、维护本部门资产。
- 普通员工：创建和维护本人草稿，提交资产申请，查看审批状态与流程记录。
- 系统管理员：配置用户、部门、角色、菜单和数据权限。

## 2. 资产分类

### 功能

- 按编码、名称、状态查询分类。
- 新增根分类或子分类。
- 修改分类名称、编码、默认折旧年限、排序、状态和备注。
- 删除未被子分类及资产台账引用的分类。

### 业务规则

- 分类编码在当前租户内不可重复，只允许字母、数字、下划线和中划线。
- 分类层级不能形成循环，不能将自身设置为上级分类。
- 停用分类可保留历史数据，但不能用于新建或修改资产台账。
- 存在下级分类或关联资产时禁止删除。

## 3. 资产台账

### 功能

- 按资产编码、名称、分类、状态、部门等条件分页查询。
- 新增、查看、修改资产基础信息。
- 选择使用部门和保管人。
- 删除仍处于“库存”状态的资产。

### 业务规则

- 资产编码在当前租户内不可重复。
- 资产名称、资产编码、资产分类和状态必填。
- 资产原值不得小于零；购置日期不得晚于当天。
- 保修到期日不得早于购置日期。
- 资产状态范围：库存、使用中、维修中、调拨中、已报废。
- 非库存资产必须通过后续领用、归还、维修、调拨或报废业务改变状态，不能直接删除。
- 查询和修改受 RuoYi 数据权限约束，字段映射为 `dept_id` 和 `keeper_id`。

## 5. 资产申请与审批

- 申请类型包括采购、领用、调拨、归还、报废，统一使用主表和多行明细模型。
- 采购申请允许填写待采购物品；其他类型必须选择现有资产，避免脱离台账流转。
- 单据号由后端生成，申请人和申请部门取当前登录用户，预估总金额由明细数量和单价汇总，前端值不作为可信来源。
- 只有 `draft`、`back`、`cancel` 状态允许编辑、删除或重新提交，且只能由申请人本人操作。
- 提交后启动 `asset_apply`：申请人提交 → 部门负责人审批 → 资产管理员审批 → 结束。
- 流程总体事件将 WarmFlow 状态同步到申请表；审批完成只表示申请获批，不直接修改资产台账。

## 6. 领用执行与资产履历

- 只有审批完成的领用申请才自动生成一张待执行领用单；数据库唯一约束与服务幂等判断共同防止重复生成。
- 审批与执行职责分离：审批人负责授权，资产管理员在实物交付后点击执行。
- 执行时再次校验来源申请、资产明细和库存状态，并通过条件更新防止同一资产被并发重复领用。
- 单次事务内完成资产状态、部门、保管人、地点更新，写入变更前后快照，再完成执行单；任一步失败均整体回滚。
- 资产履历仅允许查询，不提供修改和删除入口，并受部门/本人数据权限约束。
- 领用单状态为 `pending`、`completed`；执行后资产状态从 `0`（库存）变为 `1`（使用中）。

## 7. 归还执行

- 归还申请只能选择“使用中”且当前保管人为申请人的资产，前后端同时约束。
- 只有审批完成的归还申请才自动生成一张待执行归还单，同一申请不得重复生成。
- 执行时重新校验来源申请、使用状态和归还人，避免审批后资产已变更仍被误归还。
- 一个事务内将资产状态改为库存，清空使用部门和保管人，更新存放地点，写入履历并完成归还单。
- 归还单状态为 `pending`、`completed`；执行后资产状态从 `1`（使用中）变为 `0`（库存）。

## 8. 当前不包含

采购订单、到货验收、采购入库、实际调拨、维修、盘点、报废处置和统计大屏将在后续阶段实现。第四阶段已完成“领用→归还”双向状态闭环。

# 资产归还执行闭环

## 业务目标

归还审批通过只代表组织同意归还，不代表资产已经物理回库。平台用独立归还执行单隔离“审批授权”和“事实执行”。

```text
使用中资产 → 归还申请 → 审批通过 → 待执行归还单 → 确认回库 → 库存资产 + 归还履历
```

## 关键规则

1. 申请阶段只允许当前保管人选择自己保管且状态为“使用中”的资产。
2. 审批完成事件使用服务幂等判断和数据库唯一约束，保证一张申请只生成一张归还单。
3. 执行前再次校验申请状态、资产状态和保管人，避免审批期间数据变化造成错误回库。
4. 执行后资产变为库存，使用部门和保管人置空，存放地点取明细中的归还地点。
5. 台账更新、履历写入和执行单完成在同一事务中提交。

## 并发与审计

接口重复提交防护处理快速连点；资产更新带“仍为使用中且保管人未变”条件；执行单使用乐观锁。任一校验失败整单回滚，不会出现台账已回库但履历缺失的半完成状态。

## 面试讲解要点

这一阶段不是新增一个 CRUD 页面，而是把“领用→使用中→归还→库存”做成可追溯的双向状态机。重点可讲审批与执行分离、业务事务一致性、并发条件更新和只增不改的资产履历。
